Where Caddy's admin API is reachable from this host. No trailing slash. Three forms are accepted:

  • http://host:2019 — standard TCP (default)
  • https://host:2019 — if you've wrapped port 2019 in TLS
  • unix:///run/caddy-admin.sock — Unix domain socket (local-only, zero network exposure)

CaddyUI configures this node to ship its access logs, certificate events and runtime logs here — that is what powers Analytics, certificate status and Server Logs for it. Blank uses the fleet-wide target from Settings → Analytics (default caddyui:9019), which only works for a Caddy on the same Docker network as CaddyUI. A node on another host needs an address it can actually reach — the CaddyUI host as seen from that node, e.g. 10.8.0.1:9019 over a VPN or 192.168.1.10:9019 on a LAN — with port 9019 published on the CaddyUI container.

{{/* ── v2.42.0: data directory for certificate export ── */}}

Lets CaddyUI read the certificates this Caddy obtained and copy them to a directory after every renewal (Certificates → edit a managed certificate → Export to a directory). Mount the node's data volume into the CaddyUI container, read-only is enough — e.g. caddy_data:/caddy-data:ro under the caddyui service — and enter the mount path here. Only possible for a Caddy whose volume this CaddyUI host can see; leave blank for remote nodes.

{{/* ── v2.56.0 (issue #113): layer4 app Caddyfile block ── */}}

Paste a complete layer4 { ... } block, including the wrapper — CaddyUI sends it to this server's own admin API to adapt, and merges only the resulting apps.layer4 subtree into the config it pushes on every sync. Anything else the paste happens to adapt to is discarded. Requires a Caddy build with the caddy-l4 module compiled in — e.g. the applegater/caddyui-caddy image. Checked against this server's admin API before saving. Leave blank to run no layer4 app here (default).

Automatic deployment targets (optional — use this server as a configuration source)

Every proxy host, redirection, advanced route and Layer4 proxy you create or edit on this server in the web UI is automatically deployed to the servers ticked here too — no need to tick Also deploy to on each save. Those forms show these servers as default; the per-resource picker stays available for one-off extra targets. To keep a single resource off every other server, mark it node-local.

What this does not do: quick enable/disable toggles on hosts, bulk actions, Caddyfile import and the REST API do not deploy; resources that already exist are deployed the next time they are saved. For a one-time bulk copy use Sync from current on the target server. Certificates keep their own per-certificate targets. Deleting a resource here leaves its copies in place unless you tick Propagate deletions below.

Deploying happens as part of the save, so a target that cannot be reached can delay it by up to ~10 seconds (the failure is recorded in the Activity Log). Set targets on the source only — a server that already deploys to this one can't be chosen, so two servers can never point at each other.
