REST API Reference

Authentication

All endpoints require authentication via either a session cookie or an Authorization: Bearer <token> header. API tokens can be created on the API Tokens page (sidebar → API Tokens).

Example — Bearer token header

Authorization: Bearer caddyui_tok_abc123…

Token scopes

  • Read-only allows GET and HEAD requests only.
  • Proxy write allows writes to /api/v1/proxy-hosts and reads elsewhere.
  • Full access allows all API writes that the token owner's user account is allowed to perform.

For agent or MCP automation, create a dedicated CaddyUI user and use the narrowest token that matches the workflow. Community integrations that manage redirections, raw routes, or certificates require a full-access token from an appropriately limited user.

Requests without a valid credential receive 401 Unauthorized.

Caddy Fleet

GET /api/v1/servers

List every configured Caddy environment. The endpoint is read-only and available to every authenticated role.

The response never includes admin usernames, passwords, or configured public IPs.

    "admin_url": "http://caddy.example.com:2019",
    "type": "managed",
    "status": "online",
    "version": "v2.10.0",
    "tags": ["edge"],
    "last_contact_at": "2026-07-30T12:34:56Z"
  }
]

POST /api/v1/proxy-hosts

Create a new proxy host. Returns the created object with its assigned id.

Request body

{
  "domains": "app.example.com",
  "forward_scheme": "http",
  "forward_host": "192.168.1.10",
  "forward_port": 3000,
  "ssl_enabled": true,
  "ssl_forced": false,
  "http2_support": true,
  "websocket_support": true,
  "enabled": true,
  "compression_enabled": false,
  "cors_enabled": false,
  "cors_origins": "*",
  "block_common_exploits": false,
  "security_headers_enabled": false,
  "certificate_id": 0,
  "tags": "",
  "notes": ""
}

Response — 201 Created

{ "id": 7, "domains": "app.example.com", … }
PUT /api/v1/proxy-hosts/{id}

Replace a proxy host's configuration. Send only the fields you wish to update; omitted fields retain their current values.

Request body

{
  "forward_host": "192.168.1.20",
  "forward_port": 8080
}

Response — 200 OK

{ "id": 7, "forward_host": "192.168.1.20", "forward_port": 8080, … }
DELETE /api/v1/proxy-hosts/{id}

Delete a proxy host. The corresponding Caddy route is removed immediately.

Response

204 No Content
POST /api/v1/proxy-hosts/{id}/toggle

Toggle a proxy host between enabled and disabled. The route is added to or removed from Caddy accordingly.

Response

{ "id": 7, "enabled": false, … }
POST /api/v1/proxy-hosts/{id}/maintenance

Toggle maintenance mode on a proxy host. When active, all requests to the domain receive a branded maintenance page instead of being proxied upstream.

Response

{ "id": 7, "maintenance_mode": true, … }

Raw Routes

POST PUT /api/v1/raw-routes, /api/v1/raw-routes/{id}

Create or update an Advanced (raw) route from either caddyfile_src or json_data.

  • With caddyfile_src, the Caddyfile is authoritative: CaddyUI adapts it through Caddy and stores the result as json_data (any json_data sent alongside is ignored), and its listen set is derived from the site addresses — text that only uses the standard ports clears a custom listen set.
  • A PUT with json_data and no caddyfile_src replaces the route's JSON and clears its stored caddyfile_src, which no longer describes the route.
  • For a non-admin account the Caddyfile may only produce routes: text that also adapts to site-level settings the route cannot carry is refused with 400 — log, handle_errors, global options and any tls directive. bind is accepted only when the address it produces is one the route listens on (a custom port, which joins the route's listen set), never for a unix socket. import may only start a line, however the word is quoted, and may only name a snippet the administrator defined in the server Caddyfile; any other import is refused, and with no administrator snippets every import is. The word import may not appear anywhere else, and the text may not define snippets ((name) { … }, in any address position) or use the placeholders Caddy substitutes in snippets ({args[…]}, {args.N} with a numeric N, {block}, {blocks.NAME}). The text is read on the same tokens as Caddy's lexer produces, so text inside a quoted, backtick or heredoc value never counts as an import or a snippet definition. The text may nest blocks at most 32 levels deep, may be at most 64 KiB and may hold at most 16 import lines; each import counts toward those limits at an upper bound of what it expands to — the snippet, the snippets it imports in turn, and the arguments and block the import passes as often as the snippets use them. Every token counts as at least 4 bytes, and a site block whose addresses name several listener ports counts once per port (a site on http:// and https:// counts twice). The number of matcher references (@name) times the size of the matcher definitions may be at most 1 MiB, since Caddy copies a named matcher into every handler that names it. An import argument may not be a lone { or }, or hold the word import or a line break, and an import may not be written inside a matcher definition. The configuration Caddy adapts the text to may be at most 4 MiB, and the stored json_data at most 2 MiB (also for a JSON-only route). An administrator snippet that reads the server's environment or files ({env.…}, {file.…}, {$…}), that imports anything other than another snippet, that imports such a snippet, or that is part of an import cycle cannot be imported by a non-admin account; nor can one in which an {args…} placeholder can start a line (a placeholder after the first token of a line, as in reverse_proxy {args[0]}, is fine), one with a token made only of placeholders and braces, or one that puts the importer's block on a line with other text or inside a matcher definition. Text over any limit is refused with 400. These checks run before the text is sent to Caddy, and the administrator's snippets a non-admin account may import are always put ahead of the text Caddy adapts.
  • In the Caddyfile export, a non-admin's route is written only after the exact text is checked with Caddy again; if it is refused, does not adapt, or Caddy cannot be reached, the route is left out with an # (omitted: …) comment. A route whose Caddyfile has a global options block is always left out. Every proxy host and redirection host owned by a non-admin account is checked as well, with or without an Advanced config, and is exported as a site that answers 503 when its settings or its block break the rules the live configuration applies to that account, when its Advanced config does not adapt, or when Caddy cannot be reached to check it. A non-admin's route whose Caddyfile breaks these rules is also not deployed, and does not open its own listen addresses. A proxy host whose Advanced config cannot be applied at sync — Caddy does not adapt it, or, for a non-admin's host, it breaks these rules — answers 503 on its domains until the config is fixed, rather than being proxied without it. A non-admin's proxy host whose Advanced config imports an administrator's snippet is served with the snippet, but is exported as a site that answers 503: the export keeps import lines only for admin-owned hosts.
  • When upgrading, every non-admin route stored by an earlier version is held back from the live configuration until it has been adapted again under these rules, once. A route whose text adapts to exactly the routes it stored is kept. A route whose stored routes differ from what its text adapts to now, whose text no longer adapts or is refused, or that has no Caddyfile text (routes the paste import stored without text, JSON-only routes) is disabled, with its stored json_data cleared; a route with text comes back when it is saved again. The cleared routes are kept for administrators only (see below). Routes created or saved by this version are never taken by this check.
  • GET /api/v1/raw-routes/{id}/held-json — administrators only (403 otherwise): returns {"id": …, "held_json": "…"}, the routes the upgrade check cleared from a non-admin's route (empty when it cleared none). They may hold content an import read from the Caddy server, so they are never shown to the route's owner; an administrator can review them and restore them with a PUT of json_data.
  • For a non-admin account, an import may not be written inside another import's block, and some administrator snippets are not available (the response says only that the snippet is not available, as for an undefined name).

Request body

{
  "label": "app",
  "enabled": true,
  "caddyfile_src": "app.example.com {\n\treverse_proxy 10.0.0.5:8080\n}"
}
