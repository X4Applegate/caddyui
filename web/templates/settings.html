{{/* ── v2.11.15: AI assistant (Ollama) ── */}}
AI assistant (Ollama)

Enable a floating chat button (bottom-right) that proxies questions to a local Ollama server. Useful for "explain this proxy host", "convert this Caddyfile snippet", "suggest headers for…" etc. Runs locally on your GPU — no cloud calls.

When off, the floating button is hidden everywhere.

Default http://ollama:11434 assumes Ollama is in the same docker network. Use a full URL (e.g. http://192.168.1.10:11434) for a remote host.

Any model you've pulled into Ollama. Run ollama list on the Ollama host to see what's installed.

Pick a big enough model. The 3B-class default (llama3.2) is fast but tends to hallucinate Caddy-specific syntax — directives that don't exist, mixing up v1/v2, etc. Recommended models for actually-correct Caddy answers:
  • qwen2.5:14b — best balance of accuracy + speed on most setups
  • qwen2.5-coder:14b — sharper at config-file generation
  • gemma2:9b — solid mid-range alternative
  • llama3.1:8b — minimum viable for technical Q&A
Pull one with ollama pull qwen2.5:14b on the Ollama host, then put the exact tag in the field above.
{{/* v2.12.10: custom system prompt — overrides the built-in CaddyUI system prompt when non-empty. Lets users tune the assistant's voice, persona, or domain knowledge without writing a Modelfile. */}}

Overrides the built-in CaddyUI system prompt. Leave blank to use the default (which steers the model toward Caddy v2 syntax with concrete examples). Useful if you want a different persona, want the assistant to know about your in-house naming conventions, or want to make it more / less verbose than the default.

Tip: paste the built-in prompt's examples block (Caddyfile snippets for AdGuardHome / Nextcloud / wildcard) into your custom prompt to keep the model anchored on real syntax.
