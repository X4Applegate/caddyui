A dedicated listener cannot use a port Caddy already serves, such as 443. A shared proxy reads the first bytes of each connection on that port and takes only the ones that match — for example SSH for ssh.example.com — while normal HTTPS and everything else carries on as before. TCP only.

Needs a Caddy build with the caddy-l4 module (applegater/caddyui-caddy). Connections that match no shared proxy go on to Caddy's normal TLS and HTTP handling, untouched. SSH clients send their banner immediately, so the SSH matcher adds no delay.

Ports 80, 443 and 2019 are reserved for HTTP(S) and the Caddy admin API. Remember to open the listen port in your firewall.
