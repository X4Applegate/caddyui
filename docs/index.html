🚀 Release Roundup

CaddyUI v2.11.16 — UX & navigation polish

v2.11 is a UX cycle. v2.11.0 ships eight features — live filters on /raw-routes and /certificates, a tri-state theme toggle (auto / light / dark), a keyboard-shortcut overlay (?), Vim-style chord nav (g + letter), a sticky save bar on the proxy-host form, configured-field count badges, and richer empty states. v2.11.1 → v2.11.3 then collapse the proxy-host form by default — only Managed DNS and TLS Certificate stay open. v2.11.4 hoists the three essential SSL toggles to the form's always-visible top. v2.11.5 ships a global ⌘K / Ctrl+K command palette searching every resource. v2.11.6 brings bulk multi-select to /redirection-hosts, matching what /proxy-hosts already had. The rest of the v2.10 arc (Smart Caddyfile import, ~70 per-host options, baseline security headers) is still covered below.

⚡ UX & navigation polish v2.11.0 → v2.11.16

v2.10 added an enormous amount of surface area — ~70 per-host options, four list pages, deep forms. v2.11 makes that surface fast to navigate and forgiving to scroll through.

v2.11.0 — eight features, all UX

  • Live filters on /raw-routes and /certificates. Same pattern as /proxy-hosts and /redirection-hosts: search input above the table, JS filters rows by host / label / Caddyfile content (raw routes) or name / SAN list / owner email (certificates). Honours ?q=… deep-links so a filtered view is bookmarkable.
  • Tri-state theme toggle (auto / light / dark). The previous binary toggle locked you out of system preference the moment you clicked it. auto is now the default and actively tracks prefers-color-scheme via a matchMedia listener — explicit choices override. Cycles through the three states; icon + tooltip update to show the active mode.
  • Keyboard-shortcut overlay (?). Press ? on any page to open a modal listing every global shortcut. Esc closes; clicks outside dismiss. Bindings ignore key presses while typing in inputs / textareas / contenteditables so /, ?, etc. don't fire mid-edit.
  • Quick-nav chord shortcuts — Vim-style g + letter:
    • g d → / (dashboard)
    • g p → /proxy-hosts
    • g r → /redirection-hosts
    • g c → /certificates
    • g a → /raw-routes
    • g n → /analytics
    1.2s window for the second key; out-of-window resets the chord.
  • Sticky save bar on the proxy-host form. With ~70 options plus the form-search row, the in-form Save button is often offscreen. IntersectionObserver shows a floating Save / Cancel pill at the bottom of the viewport whenever the in-form actions row scrolls out of view. Re-uses the same <form> via the form= attribute — no duplicate state.
  • Configured-field badges on every <details> section of the proxy-host form. Each section's summary carries a small brand-coloured pill counting how many fields inside are non-default — so you can spot what's set without expanding sections one by one.
  • Richer empty states on /proxy-hosts and /redirection-hosts. Replaces the bare "No proxy hosts yet · + Create your first" with a card that explains what the resource is, offers three on-ramps (manual, paste Caddyfile, import live config), and links to the docs. Brand-tinted (proxy = brand, redir = sky) so the visual identity matches the rest of the app.

v2.11.1 → v2.11.3 — proxy-host form, collapsed by default

Three iterations on the same problem: the proxy-host form has so many <details> sections that auto-opening even half of them gives a multi-page scroll on first paint.

  • v2.11.1 — on create, every section starts collapsed so you can expand a feature, edit it, collapse it back, and move to the next. On edit, sections with configured fields auto-opened (originally).
  • v2.11.2 — wrapped the ~50-field Options & Forwarded Headers block in a <details> too. It was a plain <div> so the v2.11.1 collapse logic was skipping it. Also marked Managed DNS and TLS Certificate with data-keep-open so they stay open regardless — picked on almost every host.
  • v2.11.3 — collapse on edit too. The configured-field badges from v2.11.0 already tell you what's set, so auto-opening on edit was redundant noise. Managed DNS and TLS Certificate remain auto-open via data-keep-open.
Quick test. Open any existing proxy host: every section starts collapsed except Managed DNS and TLS Certificate. The brand-coloured number on each section's summary tells you how many fields inside are configured — click to expand and they're already filled.

v2.11.8 → v2.11.16 — fleet, AI, drag-to-reorder & more

Eight features that round out the form-reorder arc and start widening the surface beyond editing:

  • v2.11.8 — Forward Scheme / Host / Port + Test upstream hoisted to directly under Domain. The "where does this domain go?" essentials now sit beside the Domain field instead of below the SSL/DNS/Cert block. New top-of-form order: Domain → Forward → Enabled / Auto-SSL / Force-SSL → Managed DNS → TLS Cert → (everything else collapsed).
  • v2.11.9 — Bulk multi-select on /raw-routes. Same pattern /proxy-hosts already had: per-row checkbox, select-all, floating bottom bar with Enable / Disable / Delete.
  • v2.11.10 — Bulk delete on /certificates. Honours the same ownership + in-use guards as the single-row delete; checkboxes only appear on certs the viewer can edit. One syncCaddy call per batch — affected hosts revert to auto-issuance on the next sync.
  • v2.11.11 — Drag-to-reorder rows on /proxy-hosts and /redirection-hosts. ⠿ handle in the leftmost cell; HTML5 drag/drop. sort_order writes are index * 10 so manual edits can wedge between drag-saved rows without a renumber. UI-only — Caddy isn't re-synced on reorder.
  • v2.11.12 — "Recently edited" widget on the dashboard. Last 8 successful CRUD events across every resource type, colour-coded by resource and pulled from the activity log. Skips login / sync / snapshot noise so it reads as "what changed in CaddyUI".
  • v2.11.13 — Live route-JSON preview at the bottom of the proxy-host edit form. Collapsed by default; expanding shows the exact JSON the form would push, refreshing ~500ms after the last change. Useful for debugging why a header isn't being added or why a path matcher isn't firing.
  • v2.11.14 — Notifier covers Let's Encrypt / ACME-managed live certs. The existing notifier only inspected custom certs in CaddyUI's DB; production deployments using auto-issuance got no warning. v2.11.14 dials {first_domain}:443 for every enabled SSL-on proxy host once a day, reads the peer cert, and fires the same webhook + email channels when expiry is within the configured threshold.
  • v2.11.15 — AI assistant powered by local Ollama. Opt-in floating chat button (bottom-right) that proxies prompts to a local Ollama instance for "explain this proxy host", "convert this Caddyfile snippet", "suggest headers for Nextcloud", etc. Runs locally on the user's GPU — no cloud calls. Configure under Settings → AI assistant.
  • v2.11.16 — Caddy fleet status grid on the dashboard. One status card per registered Caddy server with online/offline status, host count, version, and last-seen relative timestamp. The active server (matching the picker) gets a brand-tinted ring; non-active rows show a "Switch to this server" button. Renders only when more than one Caddy server is registered.

v2.11.4 — Enabled / Auto SSL / Force SSL hoisted to the top

Three toggles are picked on almost every proxy host: Enabled, Auto SSL (Let's Encrypt), and Force SSL (HTTPS redirect). After v2.11.2 they were buried inside the collapsed Options & Forwarded Headers section, so flipping any of them required expanding a 50-field block first.

v2.11.4 lifts them out into their own always-visible row directly under the Domain names input, alongside Managed DNS and TLS Certificate as the form's "essentials" area. The Options & Forwarded Headers section keeps the rest (Verify Upstream TLS, X-Forwarded-* headers, blocking toggles, ~50 fields) collapsed by default — same data-keep-open / collapse pattern as before.

v2.11.5 — ⌘K / Ctrl+K command palette

Press ⌘K on macOS or Ctrl+K anywhere else to open a modal that searches across every Proxy Host, Redirection, Advanced route, and certificate visible to your account on the active server.

  • One-keystroke access from anywhere — works on the dashboard, settings, the analytics page, deeply-nested edit forms. You don't need to know which list page a resource lives on.
  • ↑/↓ to navigate, Enter to open, Esc to close. Or just click. Hovering with the mouse moves the highlight too.
  • Type pills colour-code each result with the same brand colour the list pages use, so the resource type registers visually before you read the label.

Backed by a new GET /api/search endpoint that returns a flat list of every visible resource, scoped through the same viewer / peer / admin permission filtering the list pages already use. The frontend caches the response per palette open with a 60-second freshness window — reopening the palette is instant; a stale cache silently re-fetches in the background.

v2.11.6 — bulk multi-select on /redirection-hosts

/proxy-hosts has had a floating bulk-action bar for a while: tick the per-row checkboxes, the bar appears at the bottom with Enable / Disable / Delete / Maintenance buttons that operate on every selected row in one shot. v2.11.6 adds the same to /redirection-hosts (sans Maintenance, which is proxy-host-specific).

  • Per-row checkbox on every desktop-table row, plus a select-all in the column header.
  • Floating bar at the bottom showing the selected count, with Enable / Disable / Delete buttons. Each successful batch triggers a single syncCaddy call instead of one-per-row.
  • Per-row ownership honoured — non-admins can only toggle / delete redirections they own. The bulk endpoints silently skip rows that don't belong to the current user.
  • Mobile card view stays checkbox-free. Bulk select on a phone screen is rare and the extra UI noise wasn't worth it — /proxy-hosts uses the same pattern.

v2.11.7 — Managed DNS + TLS Certificate hoisted to the top, Path matching + Upstream TLS collapsed

Two sections that used to live ~700 lines down — between the big Options block and the path-based upstream overrides — are now at the top of the proxy-host edit form, directly under the v2.11.4 essentials row.

  • Managed DNS moved up. Most hosts pick a DNS zone — burying it past Forward Host, Test upstream, and a 50-field options block was friction. Still data-keep-open so it's visible on both create and edit.
  • TLS Certificate moved up alongside it. Same reasoning — picked frequently, doesn't belong below 50 niche-tuning fields.

Two new collapsed sections were added to keep the visible top compact:

  • Path matching, query string, tags & notes bundles Path prefix, Strip prefix, Strip query string, Delete query params, Add query params, Tags, Notes, Color label, and Sort Order into one <details>. Routine hosts won't touch any of these on first save.
  • Upstream TLS & advanced settings bundles Upstream TLS SNI, minimum TLS version, Forward proxy URL, Upstream path prefix, Strip path suffix, and Upstream Host header. Most users never touch any of these.

The v2.11.0 section badges count configured fields inside each collapsed section, so a user editing an existing host can see at a glance which sections are non-default.

New top-of-form order.
  1. Domain names + www redirect + trailing slash
  2. Enabled / Auto SSL / Force SSL
  3. Managed DNS
  4. TLS Certificate
  5. Path matching, query string, tags & notes (collapsed)
  6. Forward Scheme + Host + Port + Test upstream
  7. Upstream TLS & advanced settings (collapsed)
  8. Options & Forwarded Headers (collapsed)

📥 Smart Caddyfile import — paste once, get the right resource type v2.10.7 → v2.10.9

This is the headline of the release. Until v2.10.6, pasting a Caddyfile into /caddyfile-import turned every site block into an Advanced (raw JSON) route — even the trivial example.com { reverse_proxy localhost:3000 } ones. They worked fine, but you lost the form-driven editor: the per-host security headers, health checks, alias management, all the things the proxy-host UI exists for.

v2.10.7 fixes that. Each pasted block is now inspected after Caddy's /adapt runs and routed to the right table:

Block looks likeImported as
host(s) + a single reverse_proxyProxy Host — full edit form
host(s) + a single redirRedirection
custom matchers, multiple handlers, layer-4, anything exoticAdvanced route — JSON preserved verbatim

The classification runs after Caddy normalises the Caddyfile, so you don't get false negatives from quirky-but-equivalent syntax. The auto-classify checkbox is on by default — uncheck it if you want the old "everything as Advanced" behaviour for full control of the JSON.

v2.10.8 — knowing what just happened

Importing 30 blocks in one paste produces 30 rows. v2.10.8 makes the result page tell you what each one became:

  • "Imported as" column in the result table — coloured pill linking to the right list page (Proxy Host → /proxy-hosts, Redirection → /redirection-hosts, Advanced → /raw-routes).
  • Per-kind tally banner — "Imported 12 routes — 8 proxy hosts · 2 redirections · 2 advanced" so you don't have to count rows to know the split.
  • SSLVerifyUpstream import — reverse_proxy blocks with transport http { tls_insecure_skip_verify } now correctly land as proxy hosts with TLS-verify off, matching the Caddyfile's intent. Previously this fell through to Advanced because the importer didn't recognise the transport-TLS shape.

v2.10.9 — rescuing older imports

If you imported your Caddyfile under v2.10.6 or earlier, your proxy-shaped blocks are sitting on /raw-routes as Advanced rows. v2.10.9 adds a "Re-classify" button at the top of /raw-routes that re-runs the v2.10.7 classifier across every visible Advanced row:

  • Each row's JSON is fed through the same classifier as the import path. Rows that now qualify as proxy or redirection get converted into the proper table; the original Advanced row is deleted in the same transaction.
  • Genuinely-Advanced rows (custom matchers, multiple handlers) are left alone — re-clicking the button is idempotent.
  • Per-row ownership is honoured — non-admins can only re-classify their own rows.
  • A confirmation prompt fires before the bulk operation, and a flash banner reports the result count when it lands back on the page.
Why this matters in practice. The proxy-host form is where ~70 of CaddyUI's options live — security headers, health checks, alias domains, managed DNS, the deploying-page poller, the v2.7.7 duplicate-domain guard, all of it. An Advanced row is an opaque JSON blob that none of those features can introspect. Re-classifying turns those rows back into editable, observable, governable proxy hosts in one click.

🔧 ~70 per-host options + path-based routing v2.10.0

v2.10.0 was the GA cut of a long preview cycle (v2.9.0 → v2.9.267). Two structural features and around seventy individual per-host options landed:

Two structural features

  • proxy_redirect_rules — path-based redirects on a proxy host, fired before the reverse_proxy. Lets you express @root path / → redir /webmail 302 as a single proxy host with one redirect rule, instead of dropping into Advanced JSON.
  • additional_upstream_rules — one proxy host can route different paths to different upstreams. The Nextcloud-style handle_path /push/* { reverse_proxy push:7867 } + handle /exapps/* { reverse_proxy harp:8780 } + handle { reverse_proxy nc:80 } pattern is now a single proxy host with two override rules plus the host's main forward target, with optional strip_prefix per rule.

~70 per-host options across four batches

Eight features per batch, four batches, plus ad-hoc additions. A non-exhaustive sample of the categories:

  • Identity headers — X-Forwarded-Method, X-Request-Original-Host, canonical-host enforcement (301 to the canonical Host for SEO consolidation)
  • Bot & admin-path blocking — built-in blocklist for AhrefsBot, SemrushBot, Bytespider, MJ12bot, etc. (legit crawlers untouched), plus 404-not-403 on /wp-admin, /.git, /.env, /phpmyadmin, /.aws, /.ssh, etc.
  • Header strip / forward toggles — strip arbitrary request headers before forwarding (symmetric with strip_response_headers), Link: rel=dns-prefetch / rel=preconnect hints, X-Robots-Tag noindex one-click
  • Health-check authentication — Basic auth or bearer token for active health probes against upstreams that require it
  • Performance — SQLite tuning + access_daily rollup wiring shrank multi-second analytics scans to ~10ms

Migrations are additive (ALTER TABLE ADD COLUMN guarded by a column-existence check), so upgrading from any v2.7.x or v2.8.x doesn't require any manual steps.

🔍 Proxy-host form search / filter v2.10.2

With ~70 fields on the proxy-host edit form, finding the one you want became its own challenge. v2.10.2 adds a search box at the top of the form that filters fields live as you type — match against the field label, hint text, or the underlying option name. Tab headers stay visible; matching fields glow, non-matches fade. Clearing the box restores the full form.

Looking for the X-Forwarded-Proto toggle? Type "forwarded". CSP override? Type "csp". Fastest way to navigate a dense form without imposing a new IA on it.

🛡️ Baseline security headers on CaddyUI's own responses v2.10.3 → v2.10.5

CaddyUI itself is a web app, served by Caddy. v2.10.3 adds a baseline security-header bundle to CaddyUI's own response chain — separate from any per-host headers you toggle on for your downstream sites. Defaults that Mozilla Observatory rates A+ out of the box:

  • Strict-Transport-Security with one-year max-age and includeSubDomains
  • X-Content-Type-Options: nosniff
  • Referrer-Policy: strict-origin-when-cross-origin
  • X-Frame-Options: DENY + Content-Security-Policy: frame-ancestors 'none' (defence in depth — older browsers honour XFO, modern ones honour CSP frame-ancestors)
  • Permissions-Policy denying camera, microphone, geolocation, payment, USB

v2.10.4 fixed a bundle-dedup bug where the initial implementation could ship two copies of the same header when both the global bundle and a per-host toggle set the same name. v2.10.5 generalised the fix: per-header response setters now go through a delete + set pattern so the upstream's value is unconditionally replaced, instead of being appended next to a CaddyUI-set value (which some clients honour differently).

If you front CaddyUI with another reverse proxy (e.g. Cloudflare in front of Caddy in front of CaddyUI), check that the outer proxy isn't also setting these headers — otherwise you'll see duplicates in the response. Either disable them on the outer layer or drop the v2.10.3 baseline (it's per-toggle in Settings).

📚 Caddyfile ↔ form-field mapping v2.10.6

Built-in docs at /docs got a new section: a side-by-side mapping of every Caddyfile directive to the proxy-host form field that produces it. Inline links from the Caddyfile-import page route you to the relevant doc anchor when a paste fails. Useful when you're hand-translating an old Caddyfile and want to know which form field corresponds to header_up, handle_errors, tls dns cloudflare, etc.

docker pull applegater/caddyui:preview   # every dev push (currently v2.11.16)
docker pull applegater/caddyui:latest    # retags every ~8 features (currently v2.11.7)
docker pull applegater/caddyui:stable    # parity with :latest
